# 에타빌더 웹 (프론트엔드)

React + Vite + TypeScript. 유저플로우 문서 v0.3의 **FE 담당 작업 전체**(P0 + P1)를 구현했어요.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 검사 + 배포용 빌드 (dist/)
```

`.env.example` 을 복사해 `.env` 로 쓰면 돼요.

| 변수 | 설명 |
| --- | --- |
| `VITE_API_URL` | 백엔드 주소 (기본 `https://hackathon23.onrender.com`) |
| `VITE_API_MODE` | `auto`(기본) · `real` · `mock` |

**auto 모드**: 서버 `/openapi.json` 에 `/api/auth/login` 이 있으면 실제 서버를 쓰고, 없으면(아직 배포 전이거나 서버가 잠들어 20초 안에 응답이 없으면) 브라우저 안 **모의 서버**(`src/mock`)로 동작해요. 모의 서버는 문서의 API 계약과 같은 형식으로 응답하므로, 실제 서버가 올라오면 코드 수정 없이 넘어가요. 모의 서버로 동작 중이면 헤더에 "모의 서버" 표시가 떠요. 시연 때는 `VITE_API_MODE=real` 로 고정하는 걸 권장해요.

시연용 계정: `demo@etabuilder.kr` / `demo1234`

## 폴더 구조

| 경로 | 역할 |
| --- | --- |
| `src/api/types.ts` | API 계약 타입 (체크리스트 항목, 시간표 조건, generate/chat/on-demand 요청·응답 등) |
| `src/api/http.ts` | fetch 래퍼: `Authorization: Bearer` 토큰, 시간 제한, 오류 문구 |
| `src/api/index.ts` | 12개 API 호출 + real/mock 자동 선택 |
| `src/state/store.tsx` | 화면 전체 상태. **draft(편집 중) / applied(마지막 생성 기준)** 이중 상태, 변경 수 계산, 챗봇·생성·스타일 흐름 |
| `src/components/*` | 로그인, 6개 패널, 상세 창 |
| `src/lib/constants.ts` | 요일, 이수구분 색, 레벨 이름, 기본 항목, 고정 문구 |
| `src/mock/*` | 모의 서버 (가상 카탈로그·졸업 기준·생성기·챗봇 해석기). 실제 서버가 있으면 번들에서 따로 로드되지 않아요 |

## 구현한 것 (문서의 FE 작업 목록 기준)

- **인증**: 이메일/비밀번호 가입·로그인, 토큰 localStorage 보관, 새로고침 시 `GET /api/auth/me` 로 복원. 저장된 이수 내역이 있으면 바로 기본 시간표 생성
- **3단 6패널 레이아웃** (좁은 화면은 시간표/과목/조건 탭)
- **졸업 요건**: 입학년도(2019~2026)·전공 드롭다운, 미지원 조합 안내 + 업로드 막기, 성적표 PDF 업로드(multipart), [샘플 성적표로 시작], "인식된 과목 N개", 네 영역 막대(0%부터), 우선 배치 과목 배치됨/미배치
- **시간표 조건**: 목표 학점 ±(9~21), 공강 요일 여러 개, 선호 시간 하나, 대학 스타일 하나 → `POST /api/checklist/style`
- **draft/applied**: 무엇을 바꿔도 [생성하기] 전까지 시간표는 그대로, "변경 N개 대기 중" 표시, 바뀐 조건엔 노란 점
- **AI 체크리스트**: 레벨형(드롭다운+체크) / 적용형(체크만), 충족·미충족·판단 불가 색 글자 + 분포 줄, "n/m 충족" 헤더, "생성하기 후 평가", 빈 상태 문구, ✕ 삭제, 직접 수정 시 `source: user`
- **AI 챗봇**: 현재 조건·체크리스트·최근 대화 6개 전송, 받은 상태로 교체 + 바뀐 항목 잠깐 강조, 로딩/오류 문구(실패 시 상태 변경 없음), 고정 안내 "수강평은 한 번에 한 과목씩…", `review_target` 이 오면 온디맨드 호출 → **교수별 수강평 순위 카드**(cached/collected/not_collected, 충족 n/총 m, 레벨, 3줄 요약, 근거)
- **추천 시간표**: 월~금 그리드(이수구분 색), 추천 순위 1/5 넘기기, 1순위 추천 이유, 블록 선택 → [고정]/[제한], 제한한 블록 흐리게, "제한한 과목" 칩 ✕, 조합 없음 시 이유 + 완화 제안 버튼(누르면 조건에 반영)
- **이번 조합 과목**: 이수구분별 묶음, 분반·교수·학점·시간·필수, 카드 클릭 → **상세 창**(AI 요약 3줄, 레벨별 근거 문장, 수강계획서 이미지), [학수번호 복사]

## 백엔드 연동

`hackathon23` 저장소 15bf1e9(유저플로우 v0.3 API 전체 구현) 기준으로 Render 서버에 붙여 확인했어요.

- 서버 응답은 `src/api/index.ts` 의 변환 함수(`toMeta`, `toRequirements`, `toTranscript`, `toMe`, `toLecture`, `toReviews`)가 화면용 형식(`src/api/types.ts`)으로 바꿔요. 서버 형식이 바뀌면 이 함수들만 고치면 돼요.
- 생성 요청에 `completed_credits`(성적표 결과 그대로)를 보내고, 조합의 `required_courses` 로 우선 배치 과목의 배치 여부를, 완화 제안의 `patch` 로 조건을 바로 고쳐요.
- 챗봇 응답에 `error` 가 있으면(AI 호출 실패) 상태를 바꾸지 않고 오류 문구만 보여줘요.
- 우주공강 키는 서버와 같은 `gap` 이에요.
